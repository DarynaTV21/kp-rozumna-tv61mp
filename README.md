# КП — Методи обчислювального інтелекту

Там, де немає точної формули чи алгоритму, рішення будують з нечітких правил, налаштовують за даними або шукають еволюційно. Практикум складається з трьох частин, по одній на такий метод.

| Частина | Що робите | Робота програми |
|---|---|---|
| 1 | будуєте задану нечітку систему з трьох підсистем, рахуєте вихід двома методами дефазифікації, змінюєте одне правило | 9 — нечіткі алгоритми прийняття рішень |
| 2 | отримуєте правила з даних субтрактивною кластеризацією й c-means, налаштовуєте модель Сугено і дивитеся на перенавчання | 10 — нейро-нечітке виведення |
| 3 | розподіляєте об'єкти між бригадами жадібним алгоритмом, генетичним алгоритмом і точним розв'язувачем | 11 — генетичні алгоритми |

**Варіант** — остання цифра вашого номера за списком. Умова частин 1 і 3 — у `variants/<варіант>/README.md`, дані частин 2 і 3 — у `variants/<варіант>/sample.csv`.

## Дані

`sample.csv` — один рядок на об'єкт. Назви колонок умовні. У кожному варіанті чотири вхідні колонки з п'яти перелічених і вихідна `service_cost_kuah`; які саме — у README варіанта. Межі в таблиці спільні для всіх варіантів.

| Колонка | Min | Max | Одиниця | Опис |
|---|---|---|---|---|
| `active_energy_mwh` | 0.003 | 6.58 | МВт·год | активна енергія за місяць |
| `reactive_energy_mvarh` | 0.004 | 2.34 | Мвар·год | реактивна енергія за місяць |
| `heat_energy_gcal` | 0.002 | 3.71 | Гкал | теплова енергія за місяць |
| `contracted_power_kw` | 5.37 | 48.5 | кВт | договірна потужність |
| `outage_hours` | 0.07 | 7.07 | год | тривалість перерв живлення за місяць |
| `service_cost_kuah` | 0.31 | 6.58 | тис. грн | вихід частини 2; у частині 3 — втрати, яких уникає обслуговування об'єкта |

Пропусків немає. Рядків — від 41 до 70.

## Частина 3

Кожен об'єкт можна доручити одній із трьох бригад або не брати в план.

| | |
|---|---|
| час на об'єкт | `t = 0.5 + contracted_power_kw / D` годин, `D` — у README варіанта |
| фонд часу бригади | у README варіанта; сума `t` об'єктів бригади не може його перевищити |
| мета | максимальна сума `service_cost_kuah` обслужених об'єктів |

## Результат

Файл `plan.csv`: рядок на кожен об'єкт `sample.csv` — план ГА з ремонтом із кроку 10 ноутбука.

| Колонка | Що це |
|---|---|
| `row` | номер рядка `sample.csv`, з 0 |
| `brigade` | 1, 2 чи 3 — номер бригади; 0 — об'єкт не обслуговується |

## Як виконувати

Ноутбук `template/kp.ipynb` веде крок за кроком. Умову частин 1 і 3 беріть із `variants/<варіант>/README.md`, дані — з `variants/<варіант>/sample.csv`, відповіді пишіть у `template/report.md`.

Бібліотеки перелічено в `requirements.txt` у корені комплекту, зокрема `scikit-fuzzy` (йому потрібен `networkx`) і `pygad`. У Google Colab завантажте в сесію ноутбук і `sample.csv` свого варіанта, поставте бібліотеки командою `!pip install scikit-fuzzy networkx pygad`, а `plan.csv` після виконання збережіть собі.

Викладач перевіряє, що `plan.csv` — допустимий план не гірший за жадібний алгоритм для вашого варіанта, звіряє числа частин 1 і 2 у звіті, переглядає код і графіки. Якщо щось не так, робота повертається на доопрацювання. Максимум — 12 балів.
